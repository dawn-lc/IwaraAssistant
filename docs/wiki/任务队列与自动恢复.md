# 任务队列与自动恢复

点工具栏图标 →「任务队列」（或在扩展选项里选「任务」页签）。列表分三组，**待办永远排在最上面**：

| 分组     | 含义                                 | 每行能做什么                                       |
| -------- | ------------------------------------ | -------------------------------------------------- |
| 需要处理 | 失败 / 检测到网盘链接 / 需要人工决定 | 「重试」或「打开视频页」（打开后这条待办自动移除） |
| 进行中   | 排队 / 下载中                        | 看进度；下载中可以「移除」，会先取消下载再删记录   |
| 已完成   | 完成 / 已交付                        | 历史记录，可「清空已结束」                         |

顶部「刷新状态」会立刻和 aria2 / iwaradl 对账，不必等定时扫描。

## 状态从哪来

| 通道     | 进度来源                                      |
| -------- | --------------------------------------------- |
| aria2    | WebSocket 事件（有的话）+ 定时对账兜底        |
| iwaradl  | 每 1 分钟轮询任务表（它没有推送）             |
| 浏览器   | `downloads` 事件（无字节进度）                |
| 打开直链 | 交付后失联，命中 `videoid` 时由浏览器下载接管 |

后台定时器（由浏览器 alarms 驱动，SW 挂起后也能唤醒）：

| alarm          | 周期   | 动作                                                    |
| -------------- | ------ | ------------------------------------------------------- |
| `ws-keepalive` | 2 min  | aria2 WebSocket 探活重连                                |
| `probe-aria2`  | 1 min  | 只拉 `tellActive`，做慢速判定与进度回写（**按需创建**） |
| `scan-aria2`   | 5 min  | `tellActive` + `tellStopped` 对账（WS 丢失、外部任务）  |
| `scan-iwaradl` | 1 min  | 有活跃 iwaradl 任务时才存在                             |
| `retry-failed` | 30 min | 队列 failed 任务按 attempts 上限自动重试                |

## 自动恢复做了什么

| 情况                                                     | 处理                                                                             |
| -------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 速度低于 **16 KiB/s** 且连续 2 次采样（每 1 分钟）仍如此 | 重新解析直链后**原地换地址**重启；进度超 98% 豁免，但速度为 0 不豁免（连接已死） |
| `error` / `removed`（403 过期直链是典型）                | 先分类：可恢复才重建；永久错误（404、重复下载、磁盘满、鉴权失败）不重试          |
| 空转的 `active`（0 连接、URI 从未尝试）                  | 先试 `pause`/`unpause` 唤醒，失败才重建                                          |
| aria2-next 3.x 的 403「永远 active」                     | 用「僵尸 active」判据逼出失败，再走重建；不会永远转圈                            |
| aria2 重启（`sessionId` 变了 / `numStoppedTotal` 倒退）  | 旧 gid 全部失效，按「GID not found」单独处理，不会把在跑任务全判失败             |

重建是**节流的**：WS 错误事件是秒级触发的，新 gid 若立刻又 403 不能无限重建。连续重建说明直链或网络本身不通，先解决网络。

## 长任务被中断是正常的

Chrome MV3 没有常驻后台。关闭浏览器、扩展更新、休眠、内存压力都会终止 service worker，**进行中的任务随之中断**，这是平台限制，扩展无法消除。

能做到的是**如实告知**：

- 「批量入库」「MediaCenter 同步」这类几分钟到几十分钟的任务把进度写进快照（`storage.session`），页面订阅 `onChanged` 实时渲染；被打断后挂载时明确显示「已中断」，而不是永远转圈。
- 存储里写着「在跑」而内存里没有对应任务时，启动阶段做**残骸归一**，按中断处理；不靠「N 秒没更新算死」的心跳超时——那些任务几分钟才写一次，用超时必然误杀。
- 批量入库还带**断点续跑**：每成功一页就推进游标，重开扩展后按钮变成「继续（第 N 页起）」。

## 其他约定

- **删不掉？** 正在下载的任务要先取消下载器再删记录（点一次「移除」变成「确认取消？」，再点一次才执行）。「已交付」的任务删记录不代表外部下载器停止。
- **清空已结束**只删终态记录（完成 / 已交付 / 失败），不碰进行中。
- **工具栏角标**显示「需要处理 + 进行中」的条数，不用打开页面也知道有没有事。
