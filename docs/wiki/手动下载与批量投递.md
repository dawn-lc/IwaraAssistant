# 手动下载与批量投递

## 视频 ID

视频 ID 是地址栏 `/video/<ID>` 里那一段，例如 `https://www.iwara.tv/video/AeGUIRO2D5vQ6F` 的 ID 是 `AeGUIRO2D5vQ6F`。

## 手动下载

悬浮菜单 →「手动下载」，可以一次投递多个：

```text
MrQuinWo22Ne22|22222222222222|AeGUIRO2D5vQ6F
```

用 `|` 分隔（全角 `｜` 同样识别）。手动下载是投递**隐藏视频**的唯一途径——列表页根本看不到它们，但知道 ID 就能下。

## 批量下载

1. 在视频列表页（首页、订阅、搜索结果、作者页）打开悬浮菜单 →「开关选择框」，或按 `Space`。
2. 勾选卡片。菜单里同时有「本页全部选中 / 本页反向选中 / 取消本页选中 / 取消所有选中」。
3. 悬浮菜单 →「下载所选」。

几点行为约定：

- **选区跨标签页共享**：在 A 标签页勾的，切到 B 标签页仍然算数。
- **同一视频只会有一条任务**（`skipped` 待办除外）。已经下过或正在下会被跳过，不会在下载器里堆出重复任务。
- 每个视频一旦有了结论（入队、失败、跳过）就自动取消勾选，不用手动清空。
- 投递之间间隔 **3 秒**，避免触发站点限流。确认自己不会滥用时可在「高级」页签开「不安全模式」把间隔降到 0。

## 去重是怎么判的

两层证据，任意一层命中都不重复投递：

1. **本地队列**：同一 `videoId` 已存在任务。
2. **下载器侧**：aria2 里已有同一视频的活 gid（用 `videoid` 反查）→ **接管**，绝不 `addUri` 第二次。同一输出路径上两个 gid 必会被 aria2 判成 `errorCode 13`，用户看到的则是「目标文件已存在」这种看不懂的假失败。

此外，扫描时会把「完成 + 失败」这类**跨状态的重复行**收敛掉（`planQueueVideoDuplicates`），所以历史遗留的重复行点一次「刷新状态」就会消失。

## 链接预检与元数据

- **第三方网盘链接检查**（默认关）：开启后，若视频简介或评论区里出现网盘链接，**不下载**，而是在「需要处理」里留一条待办。这是刻意不替你决定：请打开视频页自己选。
- **自动复制保存文件名**（默认关）：检测到网盘链接时把算好的文件名写进剪贴板，方便直接粘给网盘客户端。
- **元数据 JSON**（默认**关**）：开启后下载时会顺带写一份与视频同名的 `.json`，字段与站点的视频对象一致。

## 画质选择

「下载」页签的优先画质是一个**降级序列**（默认 `Source` → `540` → `360`，`preview` 默认排在最后且权重很低）。解析时按顺序试，取第一个拿得到的；整个序列都拿不到才会落到失败。想固定要某一档就把别的从序列里删掉。
