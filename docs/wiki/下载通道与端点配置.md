# 下载通道与端点配置

四条通道做的事一样——把解析出来的直链交给某个下载器——但可控程度差别很大。

| 通道               | 谁在下       | 进度 / 完成        | 并发由谁决定         | 端到端可取消               |
| ------------------ | ------------ | ------------------ | -------------------- | -------------------------- |
| **浏览器内建下载** | 浏览器       | 有（无字节进度）   | 扩展（1~10，默认 3） | 是                         |
| **aria2**          | aria2（RPC） | 有，含速度与连接数 | aria2 自己           | 是                         |
| **iwaradl**        | iwaradl      | 有（轮询任务表）   | iwaradl 自己         | 是                         |
| **打开直链**       | 外部下载器   | 交付后失联         | 外部                 | 否（删记录不等于对方停止） |

新装默认是浏览器通道：它不需要额外软件，且能拿到真实的完成 / 失败 / 取消。

## aria2（推荐长期使用）

### 端点怎么填

- 地址是 **JSON-RPC** 地址，带 `/jsonrpc` 路径：`http://127.0.0.1:6800/jsonrpc`。不是 aria2 的 Web 界面地址（那通常是 `:6800/`）。
- Token 填 aria2 的 `--rpc-secret`；没设就留空。
- 局域网里的 aria2：`http://192.168.x.x:6800/jsonrpc`。Firefox 产物是 MV2，可以直接用；若你自己改成了 MV3 构建，则只能用 `127.0.0.1` 或 `https`。
- 填完点「保存并自检」，它会依次检查「路径模板能否渲染 → 端点能否连通 → 浏览器权限是否还在」，并高亮出错的那一分区。

### 扩展会替你补的投递参数

上游 aria2 有几个默认值会让下载明显变慢或看不到失败：

| 参数                        | 上游默认                        | 扩展的处理                                                                                           |
| --------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `max-connection-per-server` | **1**                           | 显式补成 4（可调到 16）；只在服务端配置更低时才补，不覆盖更高的全局值                                |
| `split`                     | 4，但 `min-split-size` 默认 20M | 显式补 `split=4`，小于 40MB 的文件才会真的分段                                                       |
| `retry-wait`                | **0**                           | 补 `retry-wait=3`，让 502/503 这类瞬时错误由 aria2 自己重试                                          |
| `all-proxy`                 | —                               | **没配代理就一个键都不给**：传空串不是「继承全局」而是「不走代理」，会静默废掉你 aria2.conf 里的代理 |

代理与连接数在「下载」页签配置；这些参数都只往「更并行」的方向补，不覆盖你在 aria2 里设置的更激进的值。

### 扩展会替你盯着什么

- **任务反查**：`addUri` 的下载地址里注入 `videoid`，所以能用「gid → 视频」恢复映射，浏览器重启、SW 被杀之后还能对账。
- **不是我们投递的任务不接管**：只处理自己投递的 gid 与 `videoid` 标记命中的任务。
- **外部任务不会污染队列**：aria2 里其他软件的任务不会凭空变成扩展里的失败行。
- 状态映射与失败恢复的完整逻辑见 [docs/08-aria2-flow.md](https://github.com/dawn-lc/IwaraAssistant/blob/main/docs/08-aria2-flow.md)；队列语义见 [[任务队列与自动恢复]]。

### aria2 分支差异（会直接影响你的体验）

| 行为                                    | 上游 1.36               | aria2-next 2.4.9 | aria2-next 3.1.x              |
| --------------------------------------- | ----------------------- | ---------------- | ----------------------------- |
| 403 过期直链                            | `errorCode 22`          | `errorCode 22`   | **永远停在 `active`、不报错** |
| `probe` / `moveDownload` / `media` 字段 | 无                      | 无               | 有                            |
| `getSessionInfo` 方法名                 | `system.getSessionInfo` | 同左             | `aria2.getSessionInfo`        |

扩展会先读 `product` 与 `system.listMethods` 判断分支，再决定行为；认不出来时按上游处理（最保守的一侧）。对 3.1.x 的「僵尸 active」有专门判据：0 连接、URI 从未尝试、速度长期为 0 → 判定卡死并重建。

## iwaradl

1. 按 [iwaradl](https://github.com/Izumiko/iwaradl) 的文档配置好 API 并让它后台运行。
2. 扩展「RPC」页签：地址形如 `http://127.0.0.1:23456/api/tasks`，Token 与 iwaradl 的密钥一致。
3. 下载方式选 iwaradl。

注意：iwaradl 的任务接口只接受**文件名**（`filename_template`），目录由它自己的配置决定，所以路径模板里的目录部分对它不生效；它也没有推送，扩展按 1 分钟轮询任务表（仅在有活跃任务时才挂这条定时器）。

## 浏览器内建下载

- 只写到浏览器的下载目录：模板里的盘符与根会被去掉，子目录保留（两个宿主都自动建目录）。
- 拿不到字节进度——`downloads` API 不提供。扩展不会为它轮询 `downloads.search`，因为那会让后台常驻。
- 失败原因会被翻译成人话（没有下载权限 / 不支持该 URL / 保存失败），匹配不上时保留原文，方便上报。
- 同时下载数超过上限的任务落「排队」，前一个结束后自动开始。

## 打开直链（others）

后台开一个标签页指向富化后的直链，浏览器随即把它当成一次普通下载。扩展会尝试**接管**这次下载：命中同一视频的 `videoid` 就绑定成可追踪任务，界面上的「已交付」会升级成「进行中」。没被接管的保持「已交付」，删记录不代表外部下载器停止。
