# 调试与数据导出

## 打开调试模式

两种方式，任选其一：

- 「高级」页签打开 `isDebug`；
- **连续点击右下角水印 5 次**（写 storage 后自动 reload）。

打开后：控制台出现带 `[Debug]` 前缀的详细日志；水印显示调试标记。

## 后台日志在哪看

| 浏览器    | 入口                                                            |
| --------- | --------------------------------------------------------------- |
| Chrome 系 | `chrome://extensions` → 本扩展卡片 →「检查视图 service worker」 |
| Firefox   | `about:debugging` → 本扩展 →「检查」                            |

页面侧的日志在普通 DevTools 控制台；页内脚本（选择、菜单、水印）与后台是两个上下文，报错要分别看。

## 调试通道（主动连本机服务）

「高级」页签里有一组 **调试通道** 配置（默认关闭）。开启后，扩展会主动连接本机 `127.0.0.1:<端口>` 上的调试服务（仓库里的 `scripts/debug-bridge-server.mjs` 就是一个现成的服务端），并按它的指令回传：

- 队列与运行状态的**快照**；
- 后台的**日志环**（固定容量的环形缓冲，抓最近若干条，不用一直挂着控制台）；
- 白名单内的命令（比如触发一次对账、读某条任务的详细状态）。

设计约束：只连 `127.0.0.1`、默认关闭、命令来自白名单。完整协议见 [docs/09-debug-bridge.md](https://github.com/dawn-lc/IwaraAssistant/blob/main/docs/09-debug-bridge.md)。

## 导出数据

| 想要什么                         | 怎么做                                                                                                |
| -------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 配置 + 队列 + 视频库（完整备份） | 「迁移」页签 → 导出完整迁移包                                                                         |
| 只搬配置                         | 「迁移」页签 → 导出配置，得到一段 JSON（也可以反向粘贴导入）                                          |
| 原始视频库记录                   | 视频库在扩展自己的 IndexedDB 里，可用 DevTools → Application → IndexedDB 查看；导出请用迁移包，别手抄 |

存储分布：

- `browser.storage.local`：配置、下载队列、跨标签页选区、视频库的索引；
- `browser.storage.session`：**易失**的运行状态（长任务进度、同步游标），浏览器退出即清空；
- IndexedDB：视频库全量记录。

卸载扩展会连同上面三处一起清空——想留档先导出。

## 上报问题时请带

1. 扩展版本（扩展管理页可见）；
2. 浏览器与版本、安装方式（AMO / 临时载入 / 手动加载）；
3. 下载通道；
4. 任务队列里那条记录的**原始错误码或报文**（aria2 请附 `aria2.getVersion`，因为上游 1.36 / aria2-next 2.x / 3.x 行为不同）；
5. 调试模式下的控制台片段或日志环内容。

只有「下载失败」四个字时基本无法定位；带上前四条，绝大多数问题一轮就能说清。
