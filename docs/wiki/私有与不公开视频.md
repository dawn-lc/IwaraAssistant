# 私有与不公开视频

先把两个站点的概念分清，它们不是一回事：

| 类型                   | 谁能看                                               | 在列表 / 订阅里 |
| ---------------------- | ---------------------------------------------------- | --------------- |
| **不公开（unlisted）** | 知道链接的人                                         | 通常不出现      |
| **私有（private）**    | **仅作者的好友**（关注不够，必须互为好友且对方通过） | 不出现          |

「私有视频重试也没用」几乎都是第二种：访问控制不在扩展能绕过的范围内。去作者主页加为好友、对方通过后再点「重试」。

## 三个过滤 / 回填开关（「过滤」页签）

| 开关                                         | 作用范围                                         | 效果                                                |
| -------------------------------------------- | ------------------------------------------------ | --------------------------------------------------- |
| `filterLikedVideos` 过滤已点赞               | 所有视频列表响应                                 | 把已经点过赞的视频从结果里剔掉（时间线更干净）      |
| `filterUnlistedAndPrivate` 过滤不公开 / 私有 | **只作用于 `/videos?subscribed=true`**（订阅流） | 订阅页只显示公开内容                                |
| `addUnlistedAndPrivate` 强制显示             | 首页等常规视频列表                               | 把本地已缓存的私有 / 不公开视频**注入**到列表结果里 |

过滤与强制显示**互斥**：界面上开一个会自动关掉另一个。理由很实际——订阅流被剔掉的私有视频又被回填注入回时间线，同时开只会自相抵消。

## 强制显示是怎么拿到数据的

1. 进入视频列表页时，扩展自动请求**订阅流** `/videos?subscribed=true`（每页 50 个），把返回的私有 / 不公开视频解析并入库。
2. 之后的列表响应会把库里这些视频按发布时间插回去，于是就「显示」出来了。
3. 遍历有终止条件：**追平当月已入库的私有视频就停**，所以常态成本接近 1 个请求。
4. 自动遍历有 5 分钟最小间隔，狂切列表页不会把订阅流打成压测；「高级」页签的手动按钮不受这个限制。

前提：**必须登录并已关注作者**，否则订阅流拿不到东西。请求带 `user` / `subscribed` / `sort≠date` 的页面不触发回填（那些页面本来就是特定作者或特定排序的结果，注入只会打乱顺序）。

## 隐藏视频

隐藏视频不会出现在任何列表里，只能靠**手动输入视频 ID** 投递：悬浮菜单 →「手动下载」，多个 ID 用 `|` 分隔。见 [[手动下载与批量投递]]。

## 下载私有视频

用**与作者互为好友的账号**登录 iwara.tv 后即可下载，扩展投递时会按下载地址现取 cookie（含 HttpOnly）。登录态过期时重新登录并刷新页面。

## 已知取舍

- 回填只覆盖**订阅流**能拿到的范围（已关注作者），没有「全站私有视频扫描」这种东西——那既不可能也不该做。
- 回填进列表的顺序按发布时间插入，与站点自身的排序在边界上可能有微小差异。
