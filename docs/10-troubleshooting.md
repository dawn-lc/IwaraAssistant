# 故障排查

这份文档按「你看到了什么」组织，每一节都给出判断依据与下一步，而不是「重试一次」。功能边界与内部机制分别见 [05-features.md](05-features.md) 与 [08-aria2-flow.md](08-aria2-flow.md)。

## 0. 先确认三件事

1. **刷新 iwara 标签页**。扩展在安装或更新后不会注入已经打开的页面，这是最常见的一次性「没反应」。
2. **看任务队列，别只看页面**。页面内刻意不弹 toast、不显示进度条，结论落在系统通知、任务队列与工具栏角标上。
3. **确认通道**。「下载」页签里的下载方式决定了失败该去哪里找：浏览器通道看浏览器自己的下载管理器，aria2 看 aria2 的任务列表，「打开直链」只交付一次、之后不再追踪。

## 1. 装了扩展但页面上什么都没有

| 检查项                     | 期望                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------- |
| 是否刷新过页面             | 装完 / 更新后必须刷新 iwara 标签页                                                    |
| 当前页面类型               | 只有视频列表页（首页、订阅、搜索结果、作者页）与视频详情页有页内 UI                   |
| 「自动注入复选框」是否关闭 | 「下载」页签；关闭后仍可按 `Space` 手动开选择框                                       |
| 扩展是否真的启用           | `chrome://extensions` / `about:addons` 里确认没有报错、没有被宿主禁用                 |
| Chromium 系加载的目录      | 必须选**直接含 `manifest.json`** 的那个目录（`dist/chrome`），选它的上一级会加载失败  |
| Firefox 临时载入是否失效   | 临时载入的扩展在 Firefox 重启后失效，需要在 `about:debugging` 重新载入 `dist/firefox` |

确认以上都没问题后，看扩展的 service worker 控制台：`chrome://extensions` → 本扩展 →「检查视图 service worker」；Firefox 在 `about:debugging` →「检查」。控制台里的报错比界面更有信息量。

## 2. 点了下载，任务却进了「需要处理」

这是**刻意不下载**，不是失败。触发条件是「第三方网盘链接检查」开启，且该视频的简介或评论里出现了网盘下载链接。打开视频页自己决定用网盘还是用下载器，确认要下再点「强制下载」。

关闭检查：选项 →「下载」页签 →「第三方网盘链接检查」。「自动复制保存文件名」也在这里，它会把算好的文件名写进剪贴板，方便你粘给网盘客户端。

## 3. 解析失败 / 没有权限 / 403

按可能性排序：

1. **直链过期**（最常见的 403/404）。视频 CDN 的直链带时效，排队久了或页面放了很久才点下载就会失效。重新点一次下载即可，扩展会重新解析；aria2 通道上，`errorCode 22` 里带 `status=403` 的任务会按错误报文判定为「链接过期」并自动重建，不需要手动重试。
2. **首选画质全都拿不到**。「下载」页签的优先画质是按顺序降级尝试的，若整个序列在该视频上都不可用，就会落到失败。把首选画质调低（或加一个 `preview`）再试。
3. **登录态失效**。重新登录 iwara.tv 并刷新页面；扩展投递下载时会按下载地址现取 cookie（含 HttpOnly），过期就只能重新登录。
4. **网络被阻断**。DNS 污染、连接重置、IP 阻断都会表现为网络错误而不是 HTTP 错误。换网络或用代理后重试；代理填在「下载」页签（只对 aria2 / iwaradl 生效，浏览器通道走浏览器自己的代理设置）。

**私有 / 隐藏视频**：「私有」在 iwara 的语义是**仅好友可见**（关注不够，必须互为好友），这类访问控制不属于扩展能绕过的范围；「隐藏」视频只能靠手动输入视频 ID 投递（悬浮菜单 →「手动下载」）。

## 4. aria2 通道

| 现象                            | 判断依据与处理                                                                                                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 端点自检失败                    | 「RPC」页签填的是 `http://127.0.0.1:6800/jsonrpc` 这类 JSON-RPC 地址；带 `/jsonrpc` 路径，不是 Web 界面地址。Token 与 aria2 的 `--rpc-secret` 一致                              |
| Firefox 连不上局域网 aria2      | 本仓库的 Firefox 产物是 **MV2**，不受「MV3 扩展禁止本地明文 HTTP」的限制；若你自行改成了 MV3 构建，只能用 `127.0.0.1` 或 `https`。见 [02-cross-browser.md](02-cross-browser.md) |
| 任务在 aria2 里出现但扩展不动   | 点任务页顶部「刷新状态」立刻对账，不必等 5 分钟一次的定时扫描                                                                                                                   |
| 同一任务反复重建                | 速度低于 **16 KiB/s** 且连续两次采样（每 1 分钟一次）仍如此、或者直接失败的任务会被自动重启，这是设计行为；连续重建说明直链或网络本身不通，先解决网络                           |
| 状态长时间是 `active` 却 0 速度 | aria2-next 3.x 的 403 会永远停在 `active` 不报错（上游与 2.4.9 会给 `errorCode 22`）。本项目用「僵尸 active」判据把它逼出来重建，判据见 [08-aria2-flow.md](08-aria2-flow.md)    |
| 执行 `remove` 后任务又变成失败  | 已修复的历史问题（`removeDownloadResult` 抢在结果入表之前执行）。若在旧版本上遇到，升级                                                                                         |

自检入口：选项 →「RPC」页签 → 端点与环境自检（也会在 options 页加载、以及下载开始前跑一次）。它按「路径模板能否渲染 → 端点能否连通 → 浏览器权限是否还在」三步报错，并高亮对应分区。

## 5. iwaradl 通道

- 端点形如 `http://127.0.0.1:23456/api/tasks`，Token 与 iwaradl 的 API 密钥一致；iwaradl 必须先在后台运行。
- iwaradl 只接受文件名（`filename_template`），目录由它自己的配置决定，所以路径模板里的目录部分不会生效。
- 任务状态来自轮询 iwaradl 的 `/api/tasks`；它自己的并发上限决定了同时下几个。

## 6. 浏览器通道

- **权限被单独关掉**：扩展管理页里「下载文件」权限可以被单独禁用，此时 `downloads.download()` 直接抛错。自检会报出来，重新授予即可。
- **拒绕原因不可读**：浏览器给的原文是 `Invalid URL` 之类，扩展会把它映射成「没有下载权限 / 不支持该 URL / 保存失败」三类人话，匹配不上时保留原文——因为丢掉原始信息就无法上报。
- **保存位置**：浏览器通道只能写到浏览器的下载目录，模板里的盘符与根会被去掉（子目录保留）。想写到指定目录就用 aria2 / iwaradl，或在浏览器设置里改默认下载目录。
- **拿不到字节进度**：浏览器 `downloads` API 不提供传输进度，任务页对它只显示排队/进行中/完成。扩展不为它轮询 `downloads.search`，因为那会让后台常驻。

## 7. 任务卡住 / 重复 / 自己消失

- **卡在「排队」**：浏览器通道的并发上限（默认 3，1~10 可调）在起作用，前一个结束后自动开跑。aria2 / iwaradl 的「排队」是它们自己的并发上限。
- **同一视频出现两条**：同一 `videoId` 只允许一条任务（`skipped` 待办除外）。投递前会查 aria2 里是否已有活 gid，有就接管而不是再 `addUri` 一次——同一输出路径两个 gid 必被判成 `errorCode 13`。若在旧版本看到重复行，点「刷新状态」会收敛。
- **任务自己没了**：`.zip` 升级、浏览器关闭、休眠或内存压力会终止 Chrome 的 service worker，进行中的长任务随之中断（MV3 无法消除，见 [AGENTS.md](../AGENTS.md) 第 4 节）。重新打开扩展会自动做**残骸归一**：存储里写着「在跑」而内存里没有任务，就按中断处理，不会留下永远转圈的假状态。
- **删不掉**：正在下载的任务要先取消下载器再删记录（点一次「移除」变成「确认取消？」，再点一次才执行）。「已交付」的任务扩展这边删记录不代表外部下载器停止。

## 8. 速度慢

1. 先确认通道。浏览器通道是单流，速度取决于浏览器自身。
2. aria2 侧投递时已显式补 `max-connection-per-server` 与 `split`（默认各 4）：上游 aria2 这两个默认值是 **1** 与 20M，不显式给就是单连接、小文件不分段。可以在「下载」页签调高。
3. 查 external 因素：代理带宽、aria2 全局 `max-overall-download-limit`、站点 CDN 限速。
4. 速度低于 **16 KiB/s** 且连续两次采样（每 1 分钟一次）仍如此的任务会被自动重启（重新解析直链后原地换地址）；进度超 98% 时豁免，但速度为 0 不豁免。如果重启后仍然慢，问题在网络或站点侧。

## 9. 通知不弹 / 通知点不开

- 系统通知是唯一的结果反馈通道，先确认操作系统的浏览器通知权限没关、没有开「专注 / 勿扰」。
- Firefox 的 `notifications.create` 对未知字段会同步抛 `TypeError`，本项目已降级到最小字段集；若通知仍然不出现，先在 `about:addons` 里确认扩展没有被禁用通知。
- 通知被压掉不影响任务本身：任务队列与工具栏角标仍会更新。

## 10. 抓日志与导出数据

| 手段             | 怎么用                                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 调试模式         | 「高级」页签打开 `isDebug`，或**连续点右下角水印 5 次**；打开后控制台会带 `[Debug]` 前缀输出                                                    |
| 后台控制台       | `chrome://extensions` →「检查视图 service worker」；Firefox 在 `about:debugging` →「检查」                                                      |
| 调试通道         | 「高级」页签开启后，扩展主动连本机 `127.0.0.1:<端口>` 的调试服务，可取快照、日志环、执行白名单命令。见 [09-debug-bridge.md](09-debug-bridge.md) |
| 导出迁移包       | 「迁移」页签 → 导出：完整迁移包包含配置、队列与转换后的视频库记录，是最有用的上报材料                                                           |
| 视频库与队列数据 | IndexedDB（视频库）+ `browser.storage.local`（配置与队列），都在本机；卸载扩展会一并清空——想留档先导出                                          |

上报问题时请带上：扩展版本（扩展管理页可见）、浏览器与版本、下载通道、任务队列里那条记录的原始错误码/报文、以及调试模式下的控制台片段。没有这些信息时，「下载失败」几乎无法定位。

## 11. 这些不是 bug

- **Chrome 应用商店搜不到**：2026-10-30 被拒（内容政策 / 色情内容），属禁止项，Chromium 系只能手动加载，见 [07-install-chromium.md](07-install-chromium.md)。
- **浏览器提示「不受信任的扩展」**：非商店扩展的固定标记，无法关闭，不影响功能。
- **AMO 上的版本比仓库旧**：每次发版都要过 AMO 审核，商店永远会慢一点。
- **页面上没有进度条 / toast**：反馈通道是系统通知 + 任务队列，见本文第 0 节。
- **Chrome 关闭浏览器后任务没继续**：MV3 没有常驻后台，这是平台限制而不是配置问题。
